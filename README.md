# RemitCost · 汇款成本计算器

> **你寄回家的钱，路上少了多少？**
> 输入金额和国家，看清银行、汇款公司、数字渠道各吃掉你多少。

**线上**：[remitcalc.5202013.workers.dev](https://remitcalc.5202013.workers.dev)

## 一、这个工具为什么存在

### 问题：币圈工具救不了币圈新人

在币圈内部做工具（跟单审计、费率扫描、行情面板）有个天花板：
**受众全是已经有账号的人，注册转化率接近零。**

真正的增量在**圈外**——全球约 **1.7 亿移民工**，他们每月往家汇款，被
银行和汇款公司抽走 **6.2%** 的世界平均成本（World Bank RPW 口径），
撒哈拉以南非洲部分走廊超过 **8%**。

这些人**没有任何交易所账号**，而且他们有一个真实、具体、可量化的痛点：
**每个月被手续费吃掉多少钱。**

> 一个每年汇回 $2000 的工人 → 银行渠道成本 $228，数字渠道 $62。
> **差额 $166 是能多带回家的钱。**

这不是"炒币暴富"的叙事（那是赌性诉求，转化质量差且留不住人），
而是**成本核算**——每个靠汇款养家的人都在乎。

### 转化逻辑

```
圈外用户带着「我想省钱」的真实需求进来
   ↓ 算清这笔账（工具本身有价值，不需要注册）
   ↓ 看到数字渠道/交易所 P2P 更便宜
   ↓ 「那怎么用？」← 这是唯一自然的开户理由
   ↓ 注册链接（需求驱动，不是广告驱动）
```

**关键设计**：工具**先给价值再要转化**。不注册就能算出完整结果——
因为被强推注册的人会立刻关掉页面。

## 二、技术

单文件 Worker，数据内联，零后端。汇率抓取走 `open.er-api.com`（免密钥）。

```
fetch_data.py    → 拉汇率 + 走廊基准 → dist/data.json
src/index.html   → 模板（__DATA__ 占位）
build-worker.py  → 内联打包 → remit-worker.mjs（25KB）
```

刷新数据：`python3 fetch_data.py && python3 build-worker.py`

## 三、诚实边界（写在页面上，不只写在文档里）

- **P2P 不参与「最省」评比** —— 它有对手方风险，和持牌渠道不是一类东西。
  单独列出并标注 `ref`，成本按 1.5% 估算。
- **交易所 P2P 的前提**：需对方承接、自行承担对手方风险、部分国家商家会因风控冻结账户。
- **不保证任何渠道实际费率** —— 数字按公开平均区间估算，用户自己渠道的报价才算数。
- 页面底部保留免责声明：不构成投资建议，加密资产有价格与法规风险。
